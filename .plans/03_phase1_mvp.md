# Plan: Phase 1 MVP - Test Cases and Evals

Source instructions: `.instructions/20261107_03_phase1_mvp_test.md`
Related: `docs/PRD.md` (Phase P1), `docs/ONTOLOGY.md`, `docs/ontology.mmd`, `docs/steelwheels_erd.mmd`, `data/steelwheels.duckdb`

Goal: design and write failing unit and integration tests for Phase 1 (P1) only. No implementation logic.

## 1. Decisions

- **Scope:** AC-01, AC-02, AC-03, AC-05, AC-06, AC-07, AC-08, AC-09.
  - AC-04 is withdrawn (not applicable). Its ID stays in the PRD, marked withdrawn.
  - AC-10 is out of MVP scope.
- **Language and packages:** Python 3.14 (>=3.12 supported). New package `libs/tdf` (`src/tdf`), CLI entry point `tdf`.
- **Libraries:**
  - Click (CLI).
  - Pydantic v2 (models) and PyYAML (contracts).
  - `neo4j==6.4.1` driver, against Neo4j 5 Enterprise.
  - DuckDB (read-only source), pandas (profiling frames, via DuckDB `.df()`).
  - Pure-Python seeded generators (`random.Random`), CSV output.
  - pytest.
- **Polars:** not used in P1. Deferred.
- **Metadata store:** Neo4j. All metadata, contracts and run records are stored as ontology nodes and relationships.
- **Relationships:** derived from `docs/steelwheels_erd.mmd` (normalised). DuckDB supplies physical types only.
- **Dependencies:** pinned in root `requirements.txt`. `libs/tdf/pyproject.toml` declares the same packages with lower bounds only.
- **Contracts:** YAML, loaded into Pydantic models and stored in Neo4j.

### Provisional Architectural Decisions (P1)

These are recorded in the PRD as "Provisional (P1)" and may change once tested.

| AD | Provisional decision |
|---|---|
| AD-001 | Testing intent stored as `GenerationPolicy.intent` |
| AD-002 | Generation policies are scoped to their contract |
| AD-003 | Generator settings stored as a `params` JSON property on `ColumnGroup`, validated by Pydantic |
| AD-004 | One `ProfileSegment` named `ALL` per profile |
| AD-005 | Value sets and frequencies stored as inline JSON, capped at 100 distinct values |
| AD-006 | `RELATES_TO` carries `parent_columns`, `child_columns`, `cardinality`, `optional`. Nullable self-references (`employees.REPORTSTO`) are generated by ordering rows so each row references an earlier row, with the first row null. Any other cycle is an error |
| AD-007 | `Expectation.scope` (TABLE / COLUMN / RELATIONSHIP) plus a `target` reference |
| AD-008 | Any column overlap between column groups is an error. No coordination mechanism in P1 |
| AD-009 | `version` on contracts; `id` and `created_at` on profiles and runs |

AD-010 to AD-013 remain open and are not resolved in P1.

## 3. Test Matrix

| Area | Requirements / ACs | Example cases |
|---|---|---|
| ERD parser | FR-META-02/03/04 | 6 tables parsed; composite PK; join columns read from labels; optional `customers -> employees` link; self-reference `employees.REPORTSTO`; malformed label is an error |
| Metadata checks | FR-META-05 | FK column missing from DuckDB is reported; type mismatch is a warning, not an error |
| Dependency ordering | FR-META-06, FR-GEN-09, AC-07 | Order is offices -> employees -> customers -> orders, and products -> orderdetails; non-self cycle raises an actionable error; self-reference is accepted |
| Profiling | FR-PROF-02/03, AC-03 | Each metric correct on a small DuckDB fixture; value set produced only below the 100 cap; each observation records metric, value, column and segment |
| Contracts | FR-CON-01, FR-CON-04 to FR-CON-10, AC-06 | YAML loads into Pydantic models; unknown generator, unknown column and overlapping ownership each rejected before generation |
| Generators | FR-GEN-01/02/04/05/06/07, AC-02, AC-03, AC-05 | Same seed gives identical output; different seed differs; types correct; null rate within tolerance; categorical frequencies within tolerance; tuple generator emits only observed combinations |
| Relational generation | FR-GEN-08/10, AC-01 | Every child FK exists among generated parents; optional FK nulls allowed; requested row counts honoured; self-reference resolved in row order |
| Validation | FR-VAL-01 to FR-VAL-04, AC-09 | Outcomes SATISFIED, UNEXPECTED_VIOLATION, UNEVALUATED; corrupted CSV is caught; validator reads only CSV and graph, not generator internals |
| Output | FR-GEN-13/14 | Header and column order fixed; batched writes equal a single write |
| CLI | FR-CLI-01/02 | Each of the seven commands (`metadata`, `profile`, `contract`, `generate`, `validate`, `repair`, `report`) has `--help`; failures return non-zero exit codes |
| Neo4j integration | FR-META-01, FR-PROF-05/06, AC-08 | Registering SteelWheels creates Database, Table, Column and `RELATES_TO` nodes; two profiles of one table are distinguishable by run and segment; contract round-trips to GeneratorContract, GenerationPolicy, ColumnGroup, Generator and Expectation |
| End-to-end integration | P1 exit criterion | `tdf metadata` -> `tdf profile` -> `tdf contract load` -> `tdf generate --seed 42` -> `tdf validate` passes on SteelWheels; running generation twice gives identical CSVs |

Each test carries `@pytest.mark.req("<IDs>")` for traceability.

## 4. Verification

- `pip install -r requirements.txt && pip install -e libs/tdf` succeeds.
- `pytest --collect-only libs/tdf/tests` collects every test with no import errors.
- `pytest libs/tdf/tests -m "not neo4j"` runs; logic tests fail with `NotImplementedError` (expected red state).
- `pytest libs/tdf/tests` with Neo4j reachable: integration tests also fail as expected.
- A traceability test checks that every P1 acceptance criterion and FR in scope maps to at least one test.
- ERD parser fixture runs against the normalised `steelwheels_erd.mmd`; join columns are checked against DuckDB column names.
- `docker compose -f .devcontainer/docker-compose.yml build` must be run on the host by the developer (cannot be run from inside the container).
